## 0. 阅读指南

本文用三个等级表达约束力：

- **必须**：验收门槛，缺失即不满足需求。
- **应当**：默认行为；偏离时必须在 PR 或配置说明中给出理由。
- **可以**：可选能力，不阻塞当前里程碑。

需求编号规则：`FR-<域>-<序号>`，验收编号 `AC-<域>-<序号>`。域代码：`OV` 总览、`AU` 审计、`CP` 检查点、`MG` 迁移、`DC` 自检、`X` 横切。

本文定义的“鱼”指 DSH 中由鱼插件承载的持久化人格与行为记录，不指模型本身。本文不假设任何鱼插件一定存在；所有插件名都只是适配对象。

## 1. 背景与定位

### 1.1 生态现状

DSH 生态中的“养鱼”已经分出较细的层次。根据需求方提供的生态事实：

| 插件 | 负责 | 养鱼人可见的产物 |
|---|---|---|
| `dsh-fish` | 鱼的人格生长与自主行为 | 人格、日记、私语、行为记录 |
| `dsh-fish-river` | 多渠道接入 | 外部渠道的发言与回复 |
| `dsh-fishtank` | 状态持久化与整鱼导出 | 可导出的整鱼 JSON |
| `dsh-bili-whale-dashboard` | 特定鱼插件的配套管理界面 | 日记查看、回复审核 |

鱼本身的能力并不缺。缺的是**养鱼人这一侧**的通用工具层。

### 1.2 真实缺口

1. **日记撤不回。** `dsh-fish` 的公开文档明确写道：最坏的情况是鱼把不该看的内容写进日记，而日记撤不回。养鱼人需要一个“事前可见、事后可回”的缓冲层。
2. **多鱼、多环境隔离靠外部手段。** 官方 profile 切换只隔离插件；会话与插件存储仍然混在一起。社区需要独立 home 启动器，才能让一条鱼拥有不受干扰的数据环境。控制台必须能跨 profile、跨数据目录观察，而不是把鱼塞进同一个进程。
3. **管理后台绑定单一鱼插件。** `dsh-bili-whale-dashboard` 能看日记、审回复，但只服务 `dsh-bili-whale`。换一条鱼，养鱼人就要换一套界面。
4. **导出是“整鱼 JSON”，不是“养鱼人可理解的迁移流程”。** `dsh-fishtank` 的导出/导入很干净，但养鱼人拿到 JSON 之后仍要自己判断兼容性、敏感内容与备份策略。

### 1.3 产品定位

**Fish Keeper Console 是现有鱼插件之上的只读优先、审计导向、不干预鱼本身行为的养鱼人侧工具。**

它只做四件事：

| 动词 | 含义 | 对应能力 |
|---|---|---|
| **看得见** | 跨数据源汇总鱼的状态、日记与外部行为 | P0 总览、P0 审计 |
| **护得回** | 在重大变更前留下检查点，出问题时手动回滚 | P1 检查点 |
| **带得走** | 生成可校验、可预检的迁移包 | P1 迁移 |
| **查得清** | 用运行环境自检解释“还差什么” | P2 自检 |

它不生成对话、不写日记、不驱动鱼的行为、不调用模型。

### 1.4 设计原则

| 编号 | 原则 | 可检验的含义 |
|---|---|---|
| P-01 | 只读优先 | P0/P2 的所有代码路径不得打开源数据目录的写句柄；验收以哈希不变为准 |
| P-02 | 写操作显式化 | 检查点自动生成只读源数据；回滚、导入、删除检查点必须由养鱼人逐次确认 |
| P-03 | 适配器而非分支 | 核心代码不得出现 `if (pluginName === 'dsh-fish')`；差异落在适配器与声明式预设里 |
| P-04 | 派生数据不是源数据 | 控制台可以有自己的检查点与缓存，但不得冒充鱼插件的唯一可信源 |
| P-05 | 本地优先 | 默认不联网、不上传、不调用模型；唯一网络访问是用户显式配置的只读 HTTP 数据源 |
| P-06 | 失败可见 | 单个数据源失败必须显示为该数据源的错误状态，不得静默隐藏或伪造空数据 |
| P-07 | 卸载不破坏 | 卸载插件不得删除检查点，不得修改鱼的数据；是否清理由养鱼人决定 |

## 2. 目标用户与场景

### 2.1 目标用户

- 已在 DSH 中养了一条或多条“大肥鱼”的养鱼人。
- 同时使用多个鱼插件、多个渠道，或在不同 profile 中养不同鱼的用户。
- 对隐私、可恢复性、迁移可解释性有要求的用户。
- 愿意读 README、能提供数据目录路径的中级用户。

### 2.2 非目标用户

- 想让工具替自己“调教”鱼、自动改写人格的用户。
- 想在本项目里做鱼与鱼社交、公开广场、配对的用户。
- 不愿提供任何本地路径、希望完全云端托管的用户。
- 需要多人协作、权限分级、团队审计的团队用户（v1 不做）。

### 2.3 核心任务（Jobs To Be Done）

| 编号 | 任务 | 用户原话（示例） |
|---|---|---|
| J-01 | 日常巡检 | “我的鱼最近在外部渠道说了什么？日记里有没有不该写进去的东西？” |
| J-02 | 变更前保护 | “我要改人设了，先给我留一个能回去的点，别让我手动复制文件夹。” |
| J-03 | 事故回溯 | “这条日记是三天前写的，当时是什么状态？能回到那天吗？” |
| J-04 | 换机迁移 | “我要换电脑，给我一份干净的、能校验的包，而不是一堆 JSON。” |
| J-05 | 安装自检 | “我装完鱼插件了，还差什么配置才能开始养？” |
| J-06 | 分享展示 | “我想把成长时间线发给朋友看，但不想带上日记正文和渠道凭据。” |

### 2.4 关键用户旅程

**旅程 A：首次使用（10 分钟内）**

1. 从 README 安装 bundle，重启或在插件管理中启用。
2. 侧边栏出现 Fish Keeper 入口，打开后是空状态。
3. 点击“添加数据源”，选择预设（文件 / HTTP），填写路径或地址。
4. 面板显示连接测试结果与第一条鱼的状态卡片。
5. 如果缺少依赖，右侧自检页给出具体缺什么、怎么补。

**旅程 B：日常巡检（3 分钟内）**

1. 打开总览，扫一眼每条鱼的状态与渠道健康度。
2. 进入审计时间线，按“有风险”筛选。
3. 点开一条记录，看到命中的规则、脱敏后的正文、来源文件与时间。
4. 不修改任何源数据，关闭面板。

**旅程 C：事故回溯（5 分钟内）**

1. 在检查点列表找到日记写入前后的两个检查点。
2. 预览 diff，确认要回到的状态。
3. 点击回滚，阅读影响说明，输入确认短语。
4. 系统先为当前状态自动留一个“回滚前安全检查点”，再恢复目标文件。
5. 结果页显示恢复的文件、哈希校验结果，以及“事件流未被改写”的说明。

**旅程 D：换机迁移（15 分钟内）**

1. 在旧机器导出 `.fishkeeper` 包，选择是否包含检查点、是否使用分享模式。
2. 在新机器打开导入向导，选择包文件。
3. 预检报告列出：DSH 版本、缺失插件、目录权限、包完整性。
4. 补齐依赖后重新预检，显示“可以导入”。
5. 执行导入，得到导入结果与鱼的身份连续性说明。

### 2.5 成功标准

| 编号 | 标准 | 验证方式 |
|---|---|---|
| S-01 | 新用户按 README 在 10 分钟内看到第一条鱼 | 可用性测试，记录耗时 |
| S-02 | 事故回溯在 3 分钟内定位到风险条目或检查点 | 可用性测试 |
| S-03 | 迁移在 15 分钟内完成导出、预检、导入 | 双 profile 演练 |
| S-04 | 所有只读路径的源数据哈希不变 | 自动化验收 |
| S-05 | 零模型调用 | 依赖与网络审计 |
| S-06 | 卸载后检查点仍可读，鱼数据不受影响 | 卸载演练 |

## 3. 范围

### 3.1 v1.0 范围

- 多数据源只读总览（文件 + HTTP 两类适配器）。
- 审计时间线、可配置风险标记、脱敏展示。
- 检查点自动生成、diff 预览、手动回滚（仅限适配器声明可回滚的文件）。
- `.fishkeeper` 迁移包导出、导入前兼容性预检、事务化导入。
- 运行环境自检（人话版报告）。
- 中文/英文界面，Web 与 Desktop 共用同一套 Client 插件。

### 3.2 明确不做（非目标）

以下边界是需求的一部分。贡献者不应把“顺便加上”当成理由：

- **不做鱼的人格引擎。** 不注册对话工具、不调用模型生成鱼的回复、不驱动自主行为、不写日记。
- **不做鱼塘社区。** 不提供鱼与鱼之间的社交、公开广场、配对、排行榜。
- **不默认自动干预。** 审计只读；回滚、导入、删除检查点必须由养鱼人显式触发。
- **不绑定单一鱼插件。** 不对 `dsh-fish`、`dsh-fishtank`、`dsh-fish-river` 或任何一条鱼做硬依赖；以适配器接入。
- **不替代 DSH 的插件管理。** 不负责安装/卸载/升级鱼插件，只观测与保护。
- **不做云同步、账号体系、多人协作。**
- **不做自动内容审查或自动删除。** 风险标记只提示，不替用户做决定。
- **不读取渠道凭据内容。** 只检查文件是否存在、权限是否合理；不解析、不打印、不导出。

### 3.3 后续候选（不在本单承诺）

- 更多适配器：SQLite 状态、WebSocket 事件流、远程 DSH 实例。
- 检查点差异链压缩（在存储压力被真实用户验证后）。
- 时间线的标签与注释（本地、可导出）。
- CLI 子命令（只读状态、导出、自检）。
- 移动端只读视图。

## 4. 功能需求

### 4.1 P0 · 多鱼只读总览

**用户故事**

> 作为同时养了两条鱼的养鱼人，我想在一个面板里看到每条鱼最近的状态、渠道健康度和数据目录，这样我不用逐个打开插件后台。

**需求**

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-OV-01 | 支持配置多个数据源。每个数据源必须有稳定 `id`、显示名、适配器类型、位置（目录或 URL）、启用状态。 | P0 |
| FR-OV-02 | 至少提供两类适配器：基于本地文件的状态读取（JSON/JSONL），基于 HTTP 的只读状态读取。 | P0 |
| FR-OV-03 | 每个数据源展示：最近活动时间、当前情绪/精力摘要、最近一条私语或日记摘要、数据目录路径与占用大小。 | P0 |
| FR-OV-04 | 摘要中的日记/私语正文默认脱敏，只有用户显式展开才显示原文。 | P0 |
| FR-OV-05 | 渠道健康度必须来自运行时检查，而不是引用文档。至少覆盖：凭据文件是否存在且权限合理；桥接进程/端点是否在线（适配器可提供时）；最近一次外部行为距今是否超过配置阈值。 | P0 |
| FR-OV-06 | 只读保证：刷新、切换标签、关闭面板不得写入任何数据源目录。 | P0 |
| FR-OV-07 | 单个数据源失败时，该数据源显示错误状态与重试入口，其他数据源继续正常展示。 | P0 |
| FR-OV-08 | 空状态必须给出“添加数据源”的入口，并提供文件/HTTP 两种预设的表单与字段说明。 | P0 |
| FR-OV-09 | 数据源的新增、编辑、删除必须经过校验；删除只移除控制台配置，不删除鱼的数据。 | P0 |
| FR-OV-10 | 总览页必须显示当前实例是“可写”还是“只读降级”，以及原因。 | P0 |

**验收标准**

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC-OV-01 | 配置两个数据源：一个 `dsh-fishtank` 文件源，一个 `dsh-fish` 文件源或 HTTP 源 | 同一屏看到两条鱼的状态摘要；关闭并重新打开面板后，两个源目录的递归哈希与文件 mtime 均不变 |
| AC-OV-02 | 将其中一个数据源指向不存在的目录 | 该卡片在 2 秒内显示错误与重试；另一条鱼仍正常显示；总览不整体白屏 |
| AC-OV-03 | 凭据文件分别为 `0600`、`0644`、不存在（POSIX 环境） | 三种情况分别显示“正常”“权限过宽”“缺失”，并给出对应建议；Windows 显示“权限模型不适用”，不伪造 `0600` 结论 |
| AC-OV-04 | 在面板中切换标签、刷新、关闭 | 通过文件系统审计确认没有创建、修改、删除任何源文件 |
| AC-OV-05 | 第二个实例持有同一数据源 | 第二个实例显示“只读降级”横幅；总览仍可读；写操作入口禁用并解释原因 |
| AC-OV-06 | 一个 HTTP 源的渠道健康端点返回 500 或超时，另一个源正常 | 该源的渠道健康度显示 `error`/`unknown` 与最后成功时间；另一张卡片不受影响；60 秒内不重复打爆端点 |

**边界与错误**

- 数据目录不存在、不可读、为空、格式不识别，必须分别给出不同错误，不得统一显示“加载失败”。
- 文件在读取过程中被鱼插件改写：本次读取可以失败，但不得写入；下一次刷新应恢复。
- 数据目录包含符号链接：默认拒绝跟随到数据源根目录之外，除非用户在配置中显式允许。
- 数据源数量超过 20 个：允许配置，但总览只并发扫描前 20 个，其余显示“排队中”，避免打爆磁盘。

### 4.2 P0 · 行为审计日志

**用户故事**

> 作为养鱼人，我想把鱼在外部渠道的公开行为和日记聚合到一条时间线里，并能筛出可能包含隐私或敏感内容的条目，这样我能在事情变糟之前看见它。

**需求**

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-AU-01 | 聚合日记条目与外部渠道行为（评论、回复、发帖），按时间倒序统一展示。 | P0 |
| FR-AU-02 | 每条记录展示：时间、渠道、行为类型、正文摘要、来源数据源、可见性（公开/私密/未知）。 | P0 |
| FR-AU-03 | 支持按数据源、渠道、行为类型、时间范围、风险等级筛选；支持本地文本搜索。 | P0 |
| FR-AU-04 | 风险标记为只读高亮：命中规则时显示规则名称、类别、严重度、命中位置；不得自动删除、改写、隐藏源内容。 | P0 |
| FR-AU-05 | 默认规则集必须公开在 README 与设置页中，允许养鱼人增删、启用/停用、调整严重度。 | P0 |
| FR-AU-06 | 正文默认脱敏（邮箱、手机号、证件号、银行卡、密钥样式）；用户可对单条记录显式“显示原文”。 | P0 |
| FR-AU-07 | 时间线必须分页或虚拟化；单次扫描有字节数与条目数上限，超限时明确提示并提供缩小时间范围的入口。 | P0 |
| FR-AU-08 | 记录必须有稳定 ID，重复扫描不得产生重复条目；同一来源的编辑应更新而不是复制。 | P0 |
| FR-AU-09 | 审计层不得把日记全文持久化到控制台存储；允许内存缓存，缓存必须可丢弃、可重建。 | P0 |
| FR-AU-10 | 所有风险计算在本地完成，不调用模型、不发起网络请求。 | P0 |

**验收标准**

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC-AU-01 | 配置一个包含已知敏感词/密钥样本的日记源，并启用对应规则包（默认客观规则或 `topics.example`） | 时间线高亮该条目；详情显示命中的规则 ID 与名称；源目录哈希不变 |
| AC-AU-02 | 样本包含合法邮箱、手机号、18 位身份证号、银行卡号、`sk-` 样式密钥 | 五类均命中；身份证校验位错误的样本不命中；银行卡 Luhn 不通过的样本不命中 |
| AC-AU-03 | 10,000 条日记 + 5,000 条外部行为 | 首屏 50 条在 1 秒内出现；筛选“有风险”在 500 毫秒内返回；内存增量不超过 150 MB |
| AC-AU-04 | 点击“显示原文” | 仅当前记录展开；不写回源数据；重新打开面板后恢复默认脱敏 |
| AC-AU-05 | 同一份日记被扫描两次 | 时间线不出现重复条目；条目数稳定 |
| AC-AU-06 | 断网环境 | 审计页正常打开；除已配置的 HTTP 数据源外无任何网络请求 |
| AC-AU-07 | 浏览 100 条记录后检查数据根目录 | 不新增包含日记全文的持久化文件；日志不含正文；重启后时间线可从源重建 |

**边界与错误**

- 日记格式无法解析：跳过该行并在时间线顶部显示“有 N 行无法解析”，不静默丢弃。
- 时间字段缺失或非法：条目进入“时间未知”分组，不参与时间排序，但仍可搜索。
- 超长单条（> 200 KB）：只索引前 200 KB 用于风险扫描，详情页提示“已截断用于检测”，不修改原文。
- 规则正则导致回溯风险：规则加载时必须通过安全校验；不安全的规则拒绝启用并给出原因。

### 4.3 P1 · 检查点与手动回滚

**用户故事**

> 作为准备改人设的养鱼人，我想在鱼发生重大状态变更时自动留下检查点，出问题时能手动回到某个时间点，而不用手动复制整个目录。

**需求**

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-CP-01 | 支持可配置的“重大变更”触发器，至少覆盖：日记文件被写入或修改；人格/人设文件被修改；记忆文件发生实质性追加或覆盖。 | P1 |
| FR-CP-02 | 检查点存储必须独立于鱼的数据目录，默认位于 `~/.dsh/fishkeeper/checkpoints/<source-id>/`；卸载插件不得删除检查点。 | P1 |
| FR-CP-03 | 检查点只保存变更文件的压缩快照或引用快照，并做内容寻址去重；必须在 README 写明存储上界、单文件上限、保留策略。 | P1 |
| FR-CP-04 | 面板必须提供检查点列表、单文件 diff 预览、检查点详情（触发原因、涉及文件、大小、时间）。 | P1 |
| FR-CP-05 | 回滚对象必须是适配器在能力声明中显式标记为 `restorable` 的**可见派生文件**（如日记文件、人设文件）；被声明为“唯一可信源/只追加”的文件（如 `events.jsonl`）永远不可回滚。 | P1 |
| FR-CP-06 | 回滚必须由养鱼人显式触发，经过“影响预览 → 二次确认 → 执行 → 结果校验”四步；执行前必须自动为当前状态创建安全检查点。 | P1 |
| FR-CP-07 | 回滚不得删除、重写、截断鱼的事件流或任何未在检查点清单中的文件。 | P1 |
| FR-CP-08 | 对不支持回滚的数据源，面板必须显示“此数据源不支持回滚，检查点仅用于审计与迁移参考”，并禁用回滚按钮。 | P1 |
| FR-CP-09 | 支持固定（pin）、删除单个检查点、按保留策略自动清理；被固定的检查点不自动删除。 | P1 |
| FR-CP-10 | 多实例安全：同一数据源同时被两个控制台实例持有检查点目录时，后进者只读降级，不写入检查点，并给出明确提示。 | P1 |
| FR-CP-11 | 崩溃安全：检查点创建过程中进程被杀，重启后不得出现半成品检查点；索引必须可修复，已有检查点必须可读。 | P1 |
| FR-CP-12 | 每次回滚、删除检查点、修改保留策略都必须写入控制台自己的审计记录（不含日记全文）。 | P1 |

**验收标准**

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC-CP-01 | 在测试适配器（日记文件声明 `restorable: true`，事件流声明 `restorable: false`）上触发一次日记写入 | 5 秒内生成检查点；清单包含触发文件、前后哈希、压缩快照大小；事件流只记录哈希，不记录内容 |
| AC-CP-02 | 对 AC-CP-01 的检查点执行回滚 | 日记文件字节恢复到写入前；事件流哈希不变；回滚前自动生成了安全检查点；结果页显示校验通过 |
| AC-CP-03 | 对只追加事件流尝试回滚 | 回滚入口禁用并解释；通过文件审计确认事件流未被打开写句柄 |
| AC-CP-04 | 两个实例指向同一数据源 | 第二个实例进入只读降级；不创建检查点文件；横幅与原因可见 |
| AC-CP-05 | 在检查点写入过程中强制终止进程，重启 | 索引可读；无半成品目录被列为检查点；后续检查点可正常创建 |
| AC-CP-06 | 检查点存储超过配置上限 | 停止创建新检查点并显示告警；已有检查点不被静默删除；固定检查点保留 |
| AC-CP-07 | 回滚目标文件在检查点之后又被修改 | 显示“目标已变化”警告与三方对比；必须显式勾选“覆盖较新内容”才能继续 |

**边界与错误**

- **保护窗口**：检查点只在控制台运行且已建立基线后生成。控制台未运行期间发生的写入，重启后只能看到结果，无法恢复写入前状态；面板必须明确显示“保护起点”，README 必须建议需要保护时让控制台常驻。
- 文件编码不是 UTF-8：以字节快照回滚，diff 显示“二进制/非 UTF-8，无法预览”，但仍可回滚。
- 文件在检查点创建途中被重命名：记录为“路径变化”，不猜测新路径；下一个检查点重新绑定。
- 磁盘空间不足：检查点创建失败，记录告警，不删除旧检查点；面板显示剩余空间与建议。
- 回滚写入失败：尝试从安全检查点恢复原状；无论成功与否都显示逐文件结果，不谎报“全部成功”。

### 4.4 P1 · 迁移与分享包

**用户故事**

> 作为要换电脑的养鱼人，我想生成一份可校验、可预检的 `.fishkeeper` 包，在新环境导入前就知道缺什么，而不是导到一半失败。

**需求**

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-MG-01 | 一键生成 `.fishkeeper` 包，至少包含：鱼的数据（副本或只读引用，取决于适配器能力）、数据源元信息（插件类型、版本、路径约定）、可选的检查点子集、一份人可读清单。 | P1 |
| FR-MG-02 | 包必须带 schema 版本、创建时间、导出器版本、每个文件的 SHA-256 校验和。 | P1 |
| FR-MG-03 | 导入前必须预检：DSH 版本、所需鱼插件是否存在及版本、目标目录是否可写、包是否完整、schema 是否兼容；输出“可以导入 / 缺少依赖 / 不兼容 / 包损坏”的明确结论。 | P1 |
| FR-MG-04 | 导入必须是事务化的：先解压到临时目录并校验，再应用；任何一步失败不得留下半个鱼的数据目录。 | P1 |
| FR-MG-05 | 分享模式必须默认剔除日记正文、记忆原文、渠道凭据；默认只保留时间线元数据（时间、类型、渠道、长度、风险类别）、人格白名单快照和统计。用户可显式勾选“包含脱敏摘要”，此时才导出截断后的摘要。导出前显示“将包含什么”的预览。 | P1 |
| FR-MG-06 | 完整模式也必须默认脱敏渠道配置中的密钥；凭据永不进入包。v1 不提供“包含凭据”的导出选项；若未来提供，必须二次确认并在包清单中显著标注。 | P1 |
| FR-MG-07 | 包必须是单个文件，支持流式读写；必须限制包大小、条目数、解压后总大小，拒绝路径穿越、符号链接逃逸、zip bomb。 | P1 |
| FR-MG-08 | 导入完成后必须给出：导入了哪些文件、哪些被跳过、鱼的身份是否连续、下一步建议。 | P1 |
| FR-MG-09 | 对不支持导入的数据源，必须明确说明“仅作为参考包保存”，不得假装导入成功。 | P1 |
| FR-MG-10 | 导出/导入历史必须记录在控制台自己的审计记录中，不含正文。 | P1 |

**验收标准**

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC-MG-01 | 在 profile A 生成包，在干净 profile B 导入 | 预检报告缺失的鱼插件与版本；补全依赖后重新预检为“可以导入”；导入成功；鱼的身份字段与 A 一致。若适配器无法提供身份字段，结果显示“身份连续性未知”，不得伪造“一致” |
| AC-MG-02 | 篡改包内一个文件 | 预检报告校验和失败；不写入目标目录 |
| AC-MG-03 | 包内含 `../../evil` 路径或符号链接 | 预检直接拒绝，给出“不安全条目”列表；不产生临时目录之外的写入 |
| AC-MG-04 | 分享模式导出 | 对包做全量文本扫描，不含日记正文、记忆原文、渠道密钥；清单中包含被剔除项说明 |
| AC-MG-05 | 导入过程中强制终止进程 | 重启后目标目录无半成品；临时目录可被清理；原环境不受影响 |
| AC-MG-06 | 导入到已有同 ID 鱼的目标环境 | 明确要求用户选择“新建副本 / 覆盖（需二次确认）/ 取消”；不得静默覆盖 |

**边界与错误**

- 包版本高于当前控制台：拒绝导入并提示升级控制台，不尝试“尽力兼容”。
- 包版本低于当前控制台：允许导入，但必须列出将执行的迁移步骤。
- 目标磁盘空间不足：预检阶段就报错，不开始解压。
- 包内包含未知文件：保留在 `unknown/` 并列入清单，不执行、不加载。

### 4.5 P2 · 运行环境自检

## 5. 数据与接口契约

本节规定需求层面的契约；实现细节见[技术方案](./technical-design.zh-CN.md)。

### 5.1 数据源适配器接口

本插件不绑定单一鱼插件。贡献者通过实现只读适配器接入新数据源。适配器至少提供：

| 能力 | 要求 | 只读约束 |
|---|---|---|
| `describe()` | 返回数据源名称、类型、版本、支持的能力（日记、外部行为、检查点、回滚） | 只读 |
| `readStatus()` | 返回当前状态摘要 | 只读 |
| `readDiary(range)` | 可选；返回日记条目列表 | 只读 |
| `readExternalEvents(range)` | 可选；返回外部渠道行为记录 | 只读 |
| `snapshot(target)` | 可选；生成检查点引用或压缩快照 | 只读源数据 |
| `restore(target, checkpoint)` | 可选；仅在数据源明确支持且用户显式触发时实现 | 唯一允许写源数据的入口 |

所有适配器**不得**在未经用户显式操作的情况下调用模型的写工具或修改源数据。适配器必须声明自己可回滚的文件集合；未声明的文件一律视为不可回滚。

### 5.2 数据源配置

每个数据源至少包含：

```json
{
  "id": "fish-a",
  "displayName": "大肥鱼 A",
  "adapter": "file",
  "location": "C:/Users/me/.dsh/fish/fish-a",
  "enabled": true,
  "options": {}
}
```

- `id` 一经创建不得复用；删除后重建必须使用新 `id`，避免检查点串鱼。
- `location` 对文件源是目录，对 HTTP 源是 base URL。
- `options` 由适配器定义 schema；密钥不得出现在 `options` 中，必须走 DSH 凭据服务。

### 5.3 检查点存储

- 默认根目录：`~/.dsh/fishkeeper/`。
- 检查点：`checkpoints/<source-id>/`。
- 每个检查点必须包含 `manifest.json`，列出触发原因、涉及文件、前后哈希、快照引用、大小。
- 检查点目录必须与鱼的数据目录分离；卸载插件不得删除。
- 必须支持固定、删除、按保留策略清理；必须记录存储上界。

### 5.4 迁移包

- 扩展名：`.fishkeeper`。
- 容器：ZIP；必须包含 `manifest.json`、`README.md`（人可读清单）、`checksums.sha256`。
- `manifest.json` 至少包含：`schemaVersion`、`exportedAt`、`exporter`、`source`、`fish`、`contents[]`、`compatibility`、`privacy`。
- 导入前必须预检；导入必须事务化；分享模式必须白名单化。

### 5.5 时间与 ID

- 所有时间以 UTC ISO 8601 存储，界面按本地时区显示。
- 检查点 ID、条目 ID、数据源 ID 必须全局唯一、稳定、不可复用。
- 条目稳定 ID 由 `(sourceId, nativeId)` 或 `(sourceId, occurredAt, 内容哈希)` 生成；重复扫描不得重复计数。

## 6. 非功能需求

| 项 | 要求 | 验收方式 |
|---|---|---|
| **只读优先** | P0/P2 的所有功能不得写入鱼的数据目录；P1 的检查点自动生成只读取源数据；回滚仅在用户显式触发时写入，且只写声明可回滚的文件 | 源目录递归哈希前后对比；写句柄审计 |
| **模型调用** | 零模型调用；不得依赖 LLM SDK、不得发 prompt、不得调用 DSH 的模型服务 | 依赖清单审计、网络抓包、代码搜索 |
| **生命周期** | 所有定时器、文件监听、HTTP 轮询、API 路由必须在插件生命周期内取得，并在卸载/禁用时清理 | 卸载后句柄计数、临时目录清理、集成测试 |
| **多实例安全** | 同一数据源被第二个实例占用时，后进者只读降级，不写检查点，并明确提示 | 双实例测试 |
| **隐私** | 审计缓存与检查点可能包含日记和外部发言，不得进入公开仓库；README 必须包含“导出/分享前脱敏”提示；数据根目录权限 `0700`，文件 `0600`（POSIX） | 权限检查、仓库扫描、导出扫描 |
| **降级** | 某个适配器不可用时，面板显示该数据源错误状态，不影响其他数据源 | 故障注入测试 |
| **性能** | 参考机（4 核 CPU、SSD、16 GB 内存）：2 个数据源总览首屏 p95 ≤ 1.5 s；10,000 条时间线首屏 ≤ 1 s；筛选 ≤ 500 ms；1 MB 文件检查点创建 ≤ 200 ms；空闲 CPU < 1%；额外内存 ≤ 150 MB（100,000 条上限） | 基准脚本 |
| **兼容性** | 支持 DSH 当前稳定版及其前一个次版本；Node.js ≥ 24.9；Windows、macOS、Linux | CI 矩阵 + 手工冒烟 |
| **可访问性** | 主要流程可用键盘完成；风险状态有文字/图标，不只靠颜色；对比度满足 WCAG 2.1 AA 的普通文本要求 | 手工检查 + 组件测试 |
| **可观测性** | 本地结构化日志，默认不含正文；错误码稳定；日志可轮转 | 日志样例审查 |
| **可维护性** | 适配器有契约测试；核心无插件名分支；schema 有版本与迁移 | 代码评审 + CI |

### 9.1 风险

| 编号 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R-01 | 目标鱼插件的真实数据格式与文档不一致 | 适配器返工、验收失败 | M0 必须采集真实样本；预设做成声明式映射；允许用户自定义映射 |

| R-05 | DSH 插件 API 处于 pre-stable | 升级即坏 | 锁定 peer 版本范围；集成测试覆盖当前稳定版；抽象 Host 适配层 |
| R-06 | 检查点复制日记导致隐私二次泄露 | 用户数据风险 | 数据根目录权限、默认脱敏、README 警告、仓库禁止真实样本 |
| R-07 | Windows 无 POSIX 权限位 | 自检误报 | 显示“不适用/未知”，不伪造 `0600` |
| R-08 | 自定义正则灾难性回溯 | CPU 卡死 | 规则安全校验、长度上限、默认规则静态审查 |

## 10. 如何贡献

- 优先提交**数据源适配器**，而不是在核心逻辑里加 `if (pluginName === "dsh-fish")`。适配器必须附带 fixture 与只读契约测试。
- 任何涉及**写操作**的 PR 必须在描述中明确说明：写什么、为什么必须写、如何防止默认自动写入、失败如何回滚。
- 新功能先在 Issue 中讨论边界，确认不属于“非目标”后再实现。
- 测试至少覆盖：适配器只读性、检查点与源数据的隔离、生命周期清理、风险标记不误改数据、ZIP 路径安全。
- 用户可见文案必须同时提供中英文；新增文案必须走 locale 文件。
- 提交前运行 `pnpm test`、`pnpm run typecheck`、`pnpm run lint`、`pnpm run build`。
- 安全相关问题请走私密渠道，不要在公开 Issue 中贴真实日记或凭据。

## 附录 A · 术语表

| 术语 | 含义 |
|---|---|
| 数据源 | 控制台观察的一个鱼的数据目录或只读 HTTP 端点 |
| 适配器 | 把某种数据源映射为统一状态/日记/事件接口的只读实现 |
| 唯一可信源 | 鱼插件声明为权威、不可由外部改写的文件，例如只追加的事件流 |
| 派生数据 | 控制台基于源数据生成的缓存、检查点副本、审计记录 |
| 检查点 | 某一时刻若干受跟踪文件的内容快照与哈希清单 |
| 回滚 | 在用户显式确认下，把声明可回滚的文件恢复到检查点记录的状态 |
| 迁移包 | `.fishkeeper` 单文件 ZIP，含数据、元信息、可选检查点与人可读清单 |
| 分享模式 | 只导出展示用白名单字段、剔除正文与凭据的导出模式 |
| 只读降级 | 第二个实例检测到数据源已被占用时，仅提供读能力的状态 |

## 附录 B · 默认风险规则（摘要）

完整规则以仓库中的 `rules/default.json` 为准。默认策略遵循“客观规则默认开启，主观规则默认关闭”：

| 规则 ID | 类别 | 默认 | 严重度 | 说明 |
|---|---|---|---|---|
| `pii.email` | 隐私 | 开 | 中 | 邮箱地址 |
| `pii.phone_cn` | 隐私 | 开 | 中 | 中国大陆手机号 |
| `pii.id_cn` | 隐私 | 开 | 高 | 18 位身份证号，校验位通过才命中 |
| `pii.bank_card` | 隐私 | 开 | 高 | 13–19 位数字，Luhn 通过才命中 |
| `pii.address_cn` | 隐私 | 开 | 低 | 省市区 + 街道关键词，低置信度 |
| `secret.api_key` | 密钥 | 开 | 高 | `sk-`、`ghp_` 等常见前缀 + 长度 |
| `topic.sensitive` | 主观话题 | 关 | 中 | 需用户启用示例词表后生效 |
| `topic.controversy` | 主观话题 | 关 | 低 | 需用户启用示例词表后生效 |

默认开启的规则只覆盖可客观判定的模式；主观词表由用户显式启用，避免项目替养鱼人做价值判断。

## 附录 C · 需求裁决记录

| 编号 | 问题 | 决定 | 理由 |
|---|---|---|---|
| D-01 | 回滚是否直接改写鱼的数据文件？ | 只改写适配器声明 `restorable` 的可见派生文件；`events.jsonl` 等唯一可信源永不可回滚 | 同时满足“日记可恢复”和“不改写唯一可信源”；用能力声明而不是全局开关。这里的“派生”由适配器定义：日记/人设文件可以是可见派生物，事件流是唯一可信源 |
| D-02 | 敏感词/争议话题是否默认开启？ | 客观 PII/密钥默认开；主观话题默认关，提供示例包 | 避免社区项目替用户做价值判断，也避免默认词表过时 |
| D-03 | 检查点是否全量复制？ | 压缩快照 + 内容寻址去重；只保存变更文件；保留策略封顶 | 实现简单、恢复可靠；用上限和去重控制膨胀 |
| D-04 | 审计时间线是否落盘全文？ | 不落盘；仅内存缓存，可丢弃重建；检查点例外 | 减少隐私副本与磁盘占用 |
| D-05 | 数据源配置以谁为准？ | 插件 Config 为唯一真源；面板编辑通过配置编辑器保存 | 避免 Config 与 `sources.json` 双真源 |
| D-06 | 前后端如何通信？ | 走 DSH 现有认证 API 通道下的 `/api/fishkeeper/*` 只读/显式写路由，不新开端口 | 继承现有认证、同源与 Peer 检查，兼顾 Web 与 Desktop |
| D-07 | 跨 profile 如何工作？ | 一个控制台实例可读多个 profile 的数据目录；每个数据源同一时刻只允许一个写者 | 满足多鱼/多环境观察，避免并发写坏检查点 |
| D-08 | 分享模式包含什么？ | 白名单：时间线元数据、人格字段摘要、统计；默认不含任何正文。用户显式勾选后才附加截断的脱敏摘要；凭据永不进入 | 可分享且不泄露隐私；导出前可预览 |

**一句话验收**：一个养鱼人换电脑时，能在面板里看到“这条鱼的历史上有没有不该写进日记的东西、最近在外部渠道说了什么、如果出问题能回到哪一天”，然后带着一份干净的 `.fishkeeper` 包离开——全程不需要手动复制文件夹，也不需要让任何鱼插件改变它原有的行为。
